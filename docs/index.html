solana-pulse

Real-time Solana on-chain monitor. Reads the chain live, turns balance changes into clean SOL & SPL-token flows, and fires alerts to your terminal, a webhook, Telegram, and a live dashboard.

github.com/Bandidozx/solana-pulse

Problem

  • Watching a wallet or program for large moves usually means polling RPC or writing throwaway scripts.
  • Public endpoints rate-limit hard — you can't just stream everything at full rate.
  • Decoding every instruction for every program is fragile and doesn't generalize.

Solution

A small service you point at any program and get live, readable alerts out of — without decoding a single instruction.

Read flows, not opcodes

Computes SOL + SPL deltas from transaction meta, so it works across programs.

Built for real chains

Bounded concurrency, drop-oldest queue, 429 backoff. A slow RPC can't kill it.

How it works

onLogs(program) ─▶ bounded queue ─▶ getParsedTransaction │ │ backpressure parseTransaction (balance deltas) │ │ └──▶ evaluate (rules) ─▶ Deduper │ stdout / webhook / telegram ──▶ SSE ──▶ dashboard

What ships today

  • Program log subscription + bounded-concurrency fetch queue
  • SOL & SPL balance-delta parsing, whale thresholds, per-mint filters
  • Dedupe window, 429 cooldown, health endpoints
  • Delivery: stdout, JSON webhook, Telegram
  • Live SSE dashboard
  • Tests: npm test — 6/6 passing

Why Solami

The whole design is built for exactly what Solami sells: private RPC, the gRPC firehose, webhooks, and fast landing.

  • On a public endpoint it samples to survive the rate limit.
  • Point SOLANA_RPC_URL / SOLANA_WS_URL at Solami and it runs the full, un-sampled stream.
  • Next: consume the Yellowstone gRPC firehose directly for full throughput.

Roadmap

  • gRPC (Yellowstone) ingestion instead of onLogs
  • Address-level watchlists (alert on a specific wallet, not just magnitude)
  • Rule editor + persistence in the dashboard
  • Historical backfill and daily flow summaries
